## 2. Code changes
**Naming (old and new driver):**
- `kinova_arm.KinovaArm` reads `/joint_states`. If it has `arm_joint_1`, it uses the `arm_` names
  and `arm_mount`; otherwise the old names and `base_link`.
- `ArmModel` does the same from the URDF. `table_detector_node` uses whichever of
  `arm_mount` / `base_link` TF has.
- `place` refuses if the URDF and the driver use different names.

**URDF:**
- `save_urdf.py` saves `/arm/robot_description` as `sheppy.urdf` (the old one becomes `.urdf.old`).
- pybullet couldn't load the nightly's model:
  - its meshes are paths inside the driver's container;
  - one Robotiq joint (`arm_robotiq_85_left_inner_knuckle_joint`) failed to attach.
- `kinematics_only()` therefore loads a copy without visuals/collisions and, for the `arm_` model,
  without any gripper links. Only the arm chain is used; the fingertip is a virtual link on the flange.
- Check on the arm: `tool frame: arm says … URDF says … (0.0 cm apart)`.

**The full turn:** the first `--execute` turned the wrist a full 360° before a 3.4° adjust. The
plan works in [-180°, 180°), but the driver reports and executes raw angles. Every joint target
(our joint moves, the descent line, `kinova_arm.short_way`) now goes the short way from the current
joints.

**The hold:**
- `adjust` squares to the **nearest** hold: camera left or right, never a half turn.
- The hand points `PLACE_PITCH_DEG` = **5° down** so the bowl touches before the fingers.
  `--tilt` overrides it; 3° was tried and was worse.
- All bowl-tilt checks measure from that hold.

**The lowering (`kinova_arm.lower_line_until_contact`):**
1. Impedance on (MEDIUM), hold the start until still. It settled with **0.1 cm** of offset today,
   vs the +2.7 / −3 cm on Oct 8, so the new model seems to have fixed that.
2. The straight line down at 2 cm/s.
3. **Contact** (`CONTACT_TEST`, `TABLE_CONTACT`):
   - `velocity` (default): once moving down faster than 1 cm/s, `vz ≥ VZ_STOP` (0, or
     `TABLE_VZ_STOP`) for 2 messages in a row.
   - `force`: z up by 2 N (`TABLE_FORCE_RISE_Z`), or the whole force vector by 5 N
     (`TABLE_FORCE_RISE`).
4. **Hold** `HOLD_PRESS` = 3 mm (`TABLE_HOLD_PRESS`) below the contact point on the planned line.
   The setpoint used to be at the hand, and the arm sprang back up a little.
5. **Stay in impedance.** Switching back to position control after contact made a visible jerk.
   Only a failed lowering (no contact, an error) switches back, so the arm is never left
   compliant in mid-air.

**After contact:**
- **Opening the gripper** counts as open below 0.15, or once stopped below 0.3, within 5 s. It
  stopped at 0.11 with the fingertips on the table. If it doesn't open, the hand is **not** backed out.
- **The retreat** (`plan_retreat`, `kinova_arm.follow_line`) is 8 cm straight back, along a line we
  plan, as an impedance joint trajectory at 3 cm/s:
  - The cuRobo `go_to_ee_pose` retreat rose on the way.
  - The line starts at the hold's setpoint and lifts its 3 mm press back over the first quarter.

**Recording:**
- Every lowering writes `~/.table_place/descents/descent_<time>.csv`: every `/ee_state` message
  (pose, twist, wrench) with its phase: settle, descend, contact, open, retreat, done.
- `plot_descent.py` plots the latest one: height, the 6 velocities, force z, with a dashed line at
  each phase change.

**Debug commands:**

| Command | What it does |
|---|---|
| `status` | joints, hand and fingertips, pitch/roll, camera side, how far `place` would turn, gripper, force (no motion) |
| `reset --save` | the current pose becomes the start |
| `reset --execute` | straight up, then to that start, in impedance; then **closes the gripper** |
| `place --reset` | the same reset after placing, on ENTER |
| `retreat` | only the back-out |

`place --here` with an open gripper only warns, for empty-gripper tests.

## How to run (on the Jetson)
Start the stack: `sheppy` in `~/rammp-deployments/december_2026/` (arm_state_publisher, arm, planner;
nightly). Then:
```bash
source ~/table_ws/install/setup.zsh
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp TABLE_ARM_BACKEND=kinova TABLE_REACH="0.70,1.05"
cd ~/RAMMP-table
python3 save_urdf.py                           # after any driver update
python3 place_bowl.py status
python3 place_bowl.py reset --save             # once: the start pose for tests
python3 place_bowl.py place --here             # plan only
python3 place_bowl.py place --here --execute   # someone on the e-stop
python3 plot_descent.py
python3 place_bowl.py reset --execute
```
Copy code from the laptop: `scp *.py abra@192.168.1.11:~/RAMMP-table/`. The laptop reaches the Jetson
on the USB Ethernet adapter (192.168.1.111); Wi-Fi was on Pitt Guest.
