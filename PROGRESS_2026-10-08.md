## 1. Scene camera and table detection
- **Topics** (Orbbec driver): `/scene_camera/depth/image_raw`, `/scene_camera/depth/camera_info`,
  `/scene_camera/color/image_raw`. Depth (848×480) is **not aligned** to colour (1280×720), so the
  overlay is drawn on a grey depth picture.
- **TF works:** `scene_camera_depth_optical_frame` → `base_link` is published. The camera is at
  [0.166, 0.759, 0.347] m, looking about 14° below horizontal.
- **Floor filter:** the old `MIN_TABLE_HEIGHT = 0.0` cut right through this table (z ≈ −0.02), so the
  detection flickered. For the scene camera: `min_table_height = -0.2`, `max_plane_dist = 0.6`.
- **`TABLE_CAMERA=scene|wrist`** (default `scene`) picks the topics and floor limits
  (`table_detector_node.CAMERAS`). `save_frame.py`, `scan_and_detect.sh` (no arm move for the scene
  camera) and `place_bowl.py look` (camera pose from TF instead of joint angles + calibration) use it.
- **`save_frame.py` bug fixed:** it saved before the colour image arrived, leaving an old
  `robot_color.png`. It now waits for colour. `--overlay` saves the detector's overlay instead.
- **Live view:** Foxglove on the laptop, connected to our own `foxglove_bridge` on port **8791**. The
  lab's bridge (8780) only passes their topics; 8766 was already taken.
- Saved frames are in `herl/` (not committed).

- **Frames, measured:**
  - `/ee_state` is exactly **`end_effector_link`** (the flange): our FK on the driver's URDF matched it

- **Gripper:** the nightly driver lists no gripper controller, so the open command goes straight to

## 3. Lowering: what was tried (`place --here`, empty gripper)
| Try | What happened | Kept / changed |
|---|---|---|
| `go_to_ee_pose` to under the table | the old driver has no impedance there; the nightly one plans with cuRobo, which refused a target below the base (IK_FAIL) | lowering doesn't use cuRobo |
| "adjust" turn via `go_to_ee_pose` | cuRobo took its own path: the hand swung sideways and back | adjust is our joint move again |
| impedance (SOFT), contact = "stopped above the bottom" | it stops ~4 cm short **in free air**: a false contact (with a bowl it would have let go mid-air) | where the hand stops is no test |
| contact = slowing down | switching into impedance the hand sags ~3 cm fast, then slows: false contact. After a **cancel** the arm sprang 2.7 cm up | no cancels; a hold goal instead |
| contact = falling behind the plan | MEDIUM drifts **up** ~2.7 cm when switching, and lags more while moving: stopped in the air | settle until still first (it settled in ~2 s at +2.7 cm), still stopped at 17% |
| contact = z velocity → 0, then z force from the joint torques | **written, not run yet** | current code |

Current code (kinova backend):
1. adjust (joint move);
2. impedance on (MEDIUM), hold the start until the end effector's z velocity is ~0;
3. the straight line down at 2 cm/s, aimed 10 cm under the table (`--here`: up to 40 cm down);
4. contact = the hand's z force (estimated from the joint torques with the URDF Jacobian, `ee_force_z`)
   changes by more than 5 N from a rolling baseline, 3 readings in a row. Then hold there;
5. leaving impedance: a position goal whose setpoint **is the current joints**, so nothing jumps;
6. open the gripper, retreat 8 cm (`go_to_ee_pose`, HOLD_FIXED). No contact = the bowl isn't let go.

`--torque` uses the old rig's torque sensing (`slide_down`, position control) instead.

## How to run (on the Jetson)
```bash
source ~/table_ws/install/setup.zsh
export RMW_IMPLEMENTATION=rmw_cyclonedds_cpp TABLE_ARM_BACKEND=kinova TABLE_REACH="0.70,1.05"
cd ~/RAMMP-table
python3 table_detector_node.py                     # live detector (scene camera)
ros2 run foxglove_bridge foxglove_bridge --ros-args -p port:=8791   # Foxglove: ws://192.168.1.11:8791
python3 place_bowl.py look --no-window             # nothing moves
python3 place_bowl.py place --here                 # plan only
python3 place_bowl.py place --here --execute       # empty gripper first, hand on the e-stop
```
Code goes to the Jetson with `scp *.py abra@192.168.1.11:~/RAMMP-table/` from the laptop.
